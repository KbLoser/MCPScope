01 / 问题

工具接口扩大了服务的安全边界

MCP 将数据库、文件系统、命令执行、消息发送和基础设施能力暴露为统一工具。风险不只取决于工具名称，更取决于匿名访问、参数边界、后端权限和实际副作用。

ABSTRACTION

真实权限被工具接口遮蔽

统一的调用形式弱化了对底层数据库、文件系统和运行环境权限的感知。

METADATA

元数据已经暴露能力边界

工具名称、描述和输入 Schema 可以揭示命令执行、数据访问与外部操作能力。

AUTHORIZATION

身份检查与后端调用可能脱节

服务可以公开枚举工具，也可能在参数校验后才暴露真实的认证与授权状态。

SIDE EFFECTS

业务型工具也会改变外部状态

发送消息、管理服务或触发工作流看似常规，但同样可以产生真实且难以撤销的影响。

02 / 方法

从互联网线索到可复核证据

流程将被动发现、主动指纹和工具调用拆成独立授权边界。每一步都保留原始证据，同时限制测试规模和副作用。

  1. 01
    被动发现

    从公开来源收集候选，不连接候选服务。

    targets-discover
  2. 02
    协议指纹

    在授权范围内识别端点、传输、工具和认证状态。

    targets-scan
  3. 03
    风险筛选

    分析名称、描述和输入 Schema，聚合能力风险。

    audit
  4. 04
    受控验证

    确定性校验通过后，只执行一次人工批准调用。

    execute
  5. 05
    人工复核

    区分操作证据、调用可达和需要复核的冲突。

    review
判定原则

方法要同时限定发现、候选和验证的含义，避免把线索直接当作漏洞结论。

A

发现不等于扫描

公开索引阶段只生成候选，不主动连接未知服务。

B

候选不等于漏洞

关键词规则用于缩小审查范围，最终结论由证据等级决定。

C

验证不等于利用

测试使用无害参数、虚构标识和单次人工批准调用。

06 / 局限与安全边界

研究结论必须保留边界

MCPScope 优先减少未经授权的主动行为，并明确区分未知、不可达、被鉴权拦截、调用可达和影响已验证。

方法局限

    执行约束

    • 01

      主动指纹和工具调用必须处于明确授权范围。

    • 02

      默认只读取元数据，不执行任何 MCP 工具。

    • 03

      调用前执行确定性参数校验和人工批准。

    • 04

      每次最多调用一个候选，并保留审批摘要。

    • 05

      公开材料经过独立脱敏构建和泄露检查。
