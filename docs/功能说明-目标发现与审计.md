# MCPScope 功能说明

## 1. 产品定位

MCPScope 覆盖互联网 MCP 资产发现、风险排序、协议指纹、安全测试计划生成、受控漏洞验证和证据管理。

工具同时处理“哪里存在 MCP 服务、暴露了哪些能力、风险优先级如何”以及“如何生成安全测试计划、如何审批执行、如何保存证据和形成最终人工结论”。

本工具可以概括为：

> 一套融合互联网 MCP 目标发现、协议指纹识别、风险优先级评估、大模型辅助计划生成、确定性安全控制和人工审批验证的 MCP 安全审计框架。

它不是自动攻击工具，也不会仅凭一次响应自动确认漏洞，而是建立从目标发现到形成可复核安全证据的完整流程。

## 2. 完整流程

```text
crt.sh / HuggingFace / GitHub / npm
                ↓
        被动发现候选目标
                ↓
         人工确认授权范围
                ↓
        批量 MCP 指纹扫描
                ↓
     工具识别、风险评分和排序
                ↓
       Markdown 报告 / 历史对比
                ↓
       生成无害安全测试计划
                ↓
          确定性安全校验
                ↓
        人工审批并执行一次调用
                ↓
       保存原始证据和人工结论
```

## 3. 目标发现

工具通过公开索引收集可能部署 MCP 服务的候选地址，当前支持：

- crt.sh 证书透明度日志；
- HuggingFace Spaces；
- GitHub MCP Server 仓库主页；
- npm MCP 软件包主页。

执行命令：

```bash
./mcpscope targets-discover \
  --source crtsh \
  --source huggingface \
  --source github \
  --source npm \
  --output data/targets/candidates.json
```

目标发现阶段只查询公开索引，不连接候选 MCP 服务。系统会对候选地址执行：

- URL 格式校验；
- 主机名统一；
- 默认端口清理；
- 重复地址合并；
- 多来源归并；
- 查询参数清理；
- 嵌入式凭证拒绝；
- 来源及发现证据保存。

## 4. 授权目标批量指纹扫描

操作者从候选结果中筛选出书面授权范围内的目标后，可以执行批量 MCP 指纹扫描：

```bash
./mcpscope targets-scan \
  --input data/targets/authorized-targets.json \
  --max-targets 25 \
  --concurrency 4 \
  --authorization-ack I_HAVE_AUTHORIZATION \
  --output data/targets/fingerprint-results.json
```

该阶段读取以下信息：

- MCP 协议版本；
- 实际端点地址；
- 传输方式；
- 服务名称和版本；
- Server capabilities；
- 完整工具清单；
- 工具输入 Schema；
- 分页工具列表；
- 响应耗时；
- 端点尝试记录。

指纹扫描只执行 MCP 初始化和 `tools/list`，不会调用任何 MCP 工具。主动扫描必须提供授权确认，并默认限制扫描目标数量与并发数。

## 5. MCP 协议与传输支持

现有 MCP 探针支持：

- Streamable HTTP；
- Legacy SSE；
- WebSocket；
- stdio。

批量互联网目标扫描主要处理 HTTP 和 HTTPS；单目标发现还可以测试 WebSocket 和本地 stdio MCP 服务。

自动模式会尝试有限的标准路径：

```text
原始 URL
/mcp
/api/mcp
/sse
/mcp/sse
```

每个候选端点都有超时、最大分页数和有限回退范围，避免无限连接或无限分页。

## 6. 高风险工具识别

系统综合分析以下信息：

- 工具名称；
- 工具描述；
- `inputSchema`；
- 参数名称；
- 工具能力组合；
- 是否无需认证即可读取工具清单。

当前风险类别包括：

- 命令或代码执行；
- 文件系统访问和破坏；
- 任意 SQL 或数据库操作；
- 任意网络请求和 SSRF；
- 凭证和敏感配置访问；
- 账号、角色和权限变更；
- 基础设施变更；
- 支付、资金和交易操作；
- 邮件、消息和公开发布；
- 删除和不可逆操作；
- 工作流执行和软件安装。

每个目标会生成以下风险字段：

```text
risk_level
priority_score
risk_reasons
high_risk_candidates
```

例如，无认证暴露 `execute_sql` 工具的测试目标可以得到如下结果：

```text
风险等级：严重
优先级：97
原因：无需认证即可读取工具清单
能力：任意 SQL 或数据库操作
```

这里的“严重”表示需要优先复核的高风险能力，不等同于已经确认存在漏洞。

## 7. 资产指纹与变化跟踪

每个确认的 MCP 服务会保存：

- 托管平台推断；
- 工具数量；
- 工具名称集合哈希；
- 认证状态推断；
- 风险等级；
- 优先级分数。

当前可以识别的托管平台包括：

- HuggingFace；
- Vercel；
- Railway；
- Fly.io；
- Render；
- Cloudflare Workers；
- Google Cloud Run。

工具名称集合哈希可以辅助判断同一个 MCP 服务的工具清单是否发生变化。

## 8. 报告生成

指纹结果可以转换为 Markdown 报告：

```bash
./mcpscope targets-report \
  --input data/targets/fingerprint-results.json \
  --output data/targets/fingerprint-report.md
```

报告内容包括：

- 扫描目标数量；
- 确认 MCP 数量；
- 高风险目标数量；
- 风险等级分布；
- 认证状态分布；
- 传输方式分布；
- 托管平台分布；
- 高频工具；
- 高风险服务排序。

## 9. 扫描差异分析

系统可以离线比较两个时间点的指纹扫描结果：

```bash
./mcpscope targets-diff \
  --old data/targets/fingerprint-old.json \
  --new data/targets/fingerprint-new.json \
  --output data/targets/fingerprint-diff.json
```

差异分析能够识别：

- 新出现的 MCP 服务；
- 已消失的 MCP 服务；
- 风险等级变化；
- 新增工具；
- 移除工具；
- 工具集合变化。

该功能只读取已有结果文件，不会重新连接目标。

## 10. 安全测试计划生成

对于高风险工具，系统可以使用本地确定性模板或可选大模型生成结构化、无害的测试计划。

SQL 工具的安全测试示例：

```sql
SELECT 12345 AS audit_safe_probe;
```

命令执行工具的安全测试示例：

```bash
echo audit_safe_probe
```

测试参数仅允许使用：

- 明显虚假的资源 ID；
- `.invalid` 保留域名；
- `/tmp/mcpscope/` 临时路径；
- 零金额；
- 固定审计标记；
- 明确允许的回调地址。

## 11. 大模型的作用与安全控制

大模型只负责辅助生成测试计划，不能决定是否执行，也不能直接确认漏洞。

模型输出必须通过：

- JSON 结构校验；
- 工具输入 Schema 校验；
- 敏感凭证检测；
- SQL 安全校验；
- 命令安全校验；
- URL Allowlist 校验；
- 文件路径校验；
- 收件人和金额校验；
- 虚假目标检查。

系统采用以下决策链：

```text
大模型生成
    ↓
确定性规则否决
    ↓
人工审批
    ↓
单次执行
```

即使大模型认为计划安全，只要确定性校验不通过，计划也不能进入执行阶段。

## 12. 受控工具调用

执行 `tools/call` 时必须同时提供：

```bash
--approve
--authorization-ack I_HAVE_AUTHORIZATION
```

执行阶段还会：

- 在调用前重新校验计划；
- 计算计划 SHA-256；
- 保存人工批准记录；
- 每个候选只允许调用一次；
- 拒绝覆盖已有原始结果；
- 对敏感连接字符串进行脱敏；
- 将原始响应与分析结果分开保存。

## 13. 证据与人工复核

每次审计创建独立运行目录：

```text
data/runs/<run-id>/
├── manifest.json
├── discovery.json
├── candidates.json
├── plans/
├── approvals/
├── raw/
├── results/
└── reviews/
```

人工复核可以记录：

- `confirmed`：证据足以确认；
- `not_confirmed`：现有证据不支持漏洞结论；
- `needs_more_evidence`：需要补充授权、业务上下文或测试证据。

自动分析结果只用于证据整理和复核优先级排序，最终漏洞结论由人工确认。

## 14. 功能覆盖

| 能力 | 实现情况 |
| --- | --- |
| 互联网目标发现 | crt.sh、HuggingFace、GitHub、npm、PyPI、Smithery、Glama、PulseMCP、Censys、FOFA、Shodan |
| 批量 MCP 指纹 | 支持工具、资源、提示、服务指令、分页、端点、重定向和 Cloudflare 指纹 |
| 工具风险排序 | 支持五级风险、Schema 参数、能力组合、敏感资源和提示注入识别 |
| 历史变化分析 | 支持 SQLite 历史、趋势、纵向记录、生命周期统计、差异和持续复扫 |
| 报告格式 | JSON、JSONL、SARIF、HTML、Markdown、CSV |
| 安全测试计划 | 支持确定性模板和可选兼容接口模型 |
| 审批与证据 | 支持确定性安全校验、单次调用审批、计划哈希、原始证据和人工复核 |
| 下游集成 | 支持 Corvus、Condor、Shrike、Ibis 和可审批的事件导出 |

## 15. 当前边界

当前版本已经覆盖目标发现、指纹、风险排序、报告、历史趋势、持续复扫和下游导出能力，并保留安全计划、审批执行和证据复核。当前边界包括：

- Censys、FOFA、Shodan 和完整 Smithery 查询需要对应 API 凭据；
- watch 和消失原因分类会主动连接目标，必须限定在书面授权范围并提供授权确认；
- 认证状态主要根据无凭证访问结果和错误响应推断；
- 高风险能力识别属于静态规则判断，不能代替漏洞确认；
- 所有主动探测和工具调用都必须限定在书面授权范围内。

## 16. 总结

系统使用自身的公开索引发现模块、MCP SDK 探针、风险规则、安全计划生成器和审批机制，形成了一条完整的 MCP 安全测试流水线：

```text
发现目标 → 确认授权 → 识别能力 → 评估风险
→ 生成安全计划 → 确定性校验 → 人工批准
→ 单次验证 → 保存证据 → 人工结论
```
