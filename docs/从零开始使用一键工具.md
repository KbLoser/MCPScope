# 从零开始使用 MCPScope

本文面向第一次使用本工具的人。工具运行在本地命令行中，不需要 Docker。

## 1. 使用前提

请确认：

- 操作系统为 macOS 或 Linux；
- Python 版本为 3.11 或更高；
- Node.js 版本为 20 或更高；
- 只测试自己拥有或获得书面授权的 MCP 服务。

进入工具目录：

```bash
cd "/Users/kbloser/ESuanRong/MCP/ai-workspace/工具风险评估及漏洞检测/MCPScope"
```

首次运行前初始化配置：

```bash
cp .env.example .env
chmod +x mcpscope
./mcpscope --help
```

`mcpscope` 会自动创建 Python 虚拟环境、安装依赖，并安装 Node.js 依赖。`.env` 中的大模型配置和 `GITHUB_TOKEN` 都是可选的。

## 2. 先测试一个已授权服务

最简单的命令是 `discover`。它只执行 MCP 初始化和 `tools/list`，不会调用具体工具：

```bash
./mcpscope discover \
  --url https://authorized.example/mcp \
  --output data/one-target-discovery.json
```


```bash
./mcpscope discover \
  --url https://mcp.docs.gameanalytics.com/mcp \
  --output data/one-target-discovery.json
```
把 URL 替换成实际授权的 MCP 地址。输出中重点查看：

- `status` 是否为 `success` 或 `no_tools`；
- `transport` 和 `endpoint`；
- `protocolVersion` 和 `serverInfo`；
- `tools` 工具列表；
- `attempts` 中的连接尝试和失败原因。

如果服务是本地 stdio MCP，可以这样探测：

```bash
./mcpscope discover \
  --transport stdio \
  --command node \
  --arg server.js \
  --cwd /path/to/server
```

## 3. 批量发现候选目标

`targets-discover` 只查询公开索引，不连接候选服务器：

```bash
./mcpscope targets-discover \
  --limit-per-source 100 \
  --output data/targets/candidates.json
```

也可以只使用指定来源：

```bash
./mcpscope targets-discover \
  --source huggingface \
  --source github \
  --output data/targets/candidates.json
```

查看输出文件中的 `candidates`，人工删除没有授权的地址，只保留授权目标。可以复制成新文件：

```bash
cp data/targets/candidates.json data/targets/authorized-targets.json
```

输入也可以是 JSON 数组、JSONL，或每行一个 URL 的文本文件。

## 4. 扫描授权目标的 MCP 指纹

主动扫描前必须确认目标在书面授权范围内，并提供固定的授权确认字符串：

```bash
./mcpscope targets-scan \
  --input data/targets/authorized-targets.json \
  --max-targets 25 \
  --concurrency 4 \
  --authorization-ack I_HAVE_AUTHORIZATION \
  --output data/targets/fingerprint-results.json
```

该阶段只做初始化和 `tools/list`，不会执行 `tools/call`。结果包含服务是否确认是 MCP、认证状态推断、工具清单、高风险工具候选和优先级分数。

生成可阅读的 Markdown 报告：

```bash
./mcpscope targets-report \
  --input data/targets/fingerprint-results.json \
  --output data/targets/fingerprint-report.md
```

## 5. 为单个目标生成安全测试计划

对一个已经确认且授权的目标运行 `audit`：

```bash
./mcpscope audit \
  --url https://authorized.example/mcp \
  --plan-top 5
```


```bash
./mcpscope audit \
  --url https://mcp.docs.gameanalytics.com/mcp \
  --plan-top 5
```

该命令会读取工具列表、筛选高风险工具，并在 `data/runs/<run-id>/` 中生成：

```text
manifest.json       运行状态和目标
discovery.json      MCP 探测结果
candidates.json     高风险工具候选
plans/              测试计划及安全校验结果
```

默认使用本地确定性模板，不需要配置大模型。若需要使用 OpenAI-compatible 接口，先在 `.env` 中填写 `LLM_API_URL`、`LLM_MODEL` 和 `LLM_API_KEY`，再执行：

```bash
./mcpscope audit \
  --url https://authorized.example/mcp \
  --llm \
  --plan-top 5
```

大模型只能提出测试参数，不能直接连接或调用目标；所有输出仍需通过本地安全校验。

## 6. 人工批准后执行一次调用

从 `audit` 输出的 `Run directory` 得到运行目录，例如 `data/runs/20260810-120000-ab12cd34`。先阅读对应的计划文件：

```bash
less data/runs/20260810-120000-ab12cd34/plans/candidate-1.json
```

确认目标、工具、参数和授权范围都正确后，才执行：

```bash
./mcpscope execute \
  --run-dir data/runs/20260810-120000-ab12cd34 \
  --candidate-id 1 \
  --approve \
  --authorization-ack I_HAVE_AUTHORIZATION
```

系统会再次校验计划，并且只执行一次 `tools/call`。原始响应保存在 `raw/`，规则分析结果保存在 `results/`。如果同一候选已有调用结果，系统会拒绝重复执行。

## 7. 使用 one-click 合并流程

如果不想分别执行 `discover`、`audit` 和 `execute`，可以使用 `one-click`。默认会完成目标探测、风险筛选和计划生成，然后停在审批前：

    ./mcpscope one-click --url https://authorized.example/mcp --plan-top 5

确认计划后，显式增加执行参数即可继续完成一次受控调用：

    ./mcpscope one-click --url https://authorized.example/mcp --plan-top 5 --execute --candidate-id 1 --approve --authorization-ack I_HAVE_AUTHORIZATION

该命令最多调用一个候选工具一次，不会自动批量执行所有高风险工具。也可以在执行后追加 `--review-decision` 和 `--review-notes`，记录人工结论。

## 8. 记录最终人工结论

测试人员根据原始响应、预期测试标记和实际安全影响记录结论：

```bash
./mcpscope review \
  --run-dir data/runs/20260810-120000-ab12cd34 \
  --candidate-id 1 \
  --decision needs_more_evidence \
  --notes "需要服务所有者确认测试账号和数据范围"
```

可选结论为：

- `confirmed`：证据支持漏洞成立；
- `not_confirmed`：当前证据不足以确认；
- `needs_more_evidence`：需要补充授权、响应或业务证据。

## 9. 如何理解扫描结果

工具把无认证问题分为三个层次：

- U1：无凭证即可初始化并读取 `tools/list`；
- U2：无凭证调用 `tools/call` 能到达工具处理逻辑；
- U3：调用造成非公开数据泄露或敏感状态变化。

因此，工具列表中出现 `execute_sql`、文件操作或命令执行等高风险工具，只表示需要优先复核；`tools/list` 成功也不能单独证明工具可调用或漏洞已经确认。

## 10. 常用结果位置

```text
data/targets/                 批量发现和指纹扫描结果
data/runs/<run-id>/           单次审计运行目录
  manifest.json               状态
  candidates.json             风险候选
  plans/                      测试计划
  approvals/                  批准记录
  raw/                        原始调用结果
  results/                    自动分析结果
  reviews/                    人工结论
```

## 11. 安全注意事项

- 不要对未授权的公网目标执行 `targets-scan`、`audit` 或 `execute`。
- 不要把 `.env`、令牌、真实目标清单或原始生产数据提交到 GitHub。
- `targets-discover` 是被动发现；`targets-scan` 和 `audit` 会连接目标；`execute` 才会调用具体工具。
- 论文或报告中应分别统计“目标发现”“高风险能力识别”和“漏洞确认”，不要把三者混为同一个指标。

各命令可简单理解为：

  - discover：读取单个已授权 MCP 服务的工具清单。
  - targets-discover：从公开索引发现候选地址。
  - targets-scan：批量探测经过授权的目标。
  - targets-report：把扫描结果生成 Markdown 报告。
  - targets-diff：比较两次扫描结果。
  - audit：筛选高风险工具并生成测试计划，不调用工具。
  - execute：审批后执行一次 tools/call。
  - review：记录最终人工判断。
