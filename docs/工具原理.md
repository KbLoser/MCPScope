# MCPScope 工作原理

## 1. 工具定位

本工具用于在授权范围内完成 MCP 服务发现、协议识别、高风险工具筛选、安全验证和证据保存。它的核心目标不是自动攻击目标，而是把分散的测试步骤组织为一条可重复、可审计的流程。

```text
公开索引
  -> 候选目标发现
  -> 人工确认授权范围
  -> MCP 协议探测
  -> 高风险能力识别
  -> 安全测试计划生成
  -> 规则校验与人工审批
  -> 单次工具调用
  -> 证据分析与人工定性
```

## 2. 候选目标发现

`targets-discover` 从 crt.sh、HuggingFace、GitHub 和 npm 等公开索引中提取可能的 MCP 服务地址。该阶段只访问公开索引，不连接候选服务器。

系统会规范化 URL、去除查询参数、拒绝包含账号或密码的地址、合并重复目标，并保留来源和发现证据。此时得到的只是“可能存在 MCP 服务的地址”，还不能认定目标真实运行了 MCP。

## 3. MCP 协议识别

在操作者确认目标属于授权范围后，`targets-scan` 使用 MCP SDK 与目标建立连接，依次尝试有限的标准端点和传输方式，包括 Streamable HTTP、SSE 和 WebSocket。单目标模式还支持本地 stdio 服务。

探针完成 MCP 初始化并调用只读的 `tools/list`，采集协议版本、服务信息、传输方式、工具名称、工具描述和输入 Schema。它不会在这一阶段调用具体工具。

如果未提供凭证仍能完成初始化和 `tools/list`，系统将认证状态标记为 `none`；如果响应中出现 401、403 或明确的认证错误，则标记为 `required`；无法可靠判断时标记为 `unknown`。

## 4. 高风险能力识别

系统使用确定性规则分析工具名称、描述和 `inputSchema`，识别命令执行、文件访问、任意 SQL、SSRF、凭证读取、权限变更、基础设施操作、资金交易、外部消息和删除操作等高风险能力。

风险评分综合考虑以下因素：

- 工具能力的危险程度；
- 是否在无认证状态下暴露工具清单；
- 同一服务是否组合暴露多种危险能力；
- 命中的高风险工具数量。

该结果用于排序测试优先级。发现高风险工具只说明服务暴露了敏感能力，不等于该工具可被无认证调用，也不等于漏洞已经成立。

## 5. 安全测试计划生成

`audit` 根据高风险工具的 Schema 生成结构化测试参数。默认使用本地模板，也可以选择由大模型辅助理解复杂参数并生成计划。

大模型只负责提出候选参数，不直接连接目标，也没有执行权限。生成结果还必须通过本地确定性校验，包括 JSON Schema、SQL、命令、URL、文件路径、收件人、凭证和测试标记检查。例如 SQL 测试只允许无副作用的固定查询，文件路径限制在 `/tmp/mcpscope/`，外部 URL 必须在显式允许列表中。

## 6. 受控调用与漏洞判断

只有测试计划通过规则校验，并且操作者同时提供人工批准和授权确认后，`execute` 才会执行一次 `tools/call`。系统禁止同一候选被重复执行，并保存请求参数、响应、错误、端点和时间等原始证据，同时对常见凭证字段进行脱敏。

无认证问题可以分为三个层次：

- U1，接口暴露：无凭证即可完成初始化和 `tools/list`；
- U2，调用可达：无凭证调用 `tools/call`，请求到达工具处理逻辑；
- U3，影响确认：调用造成非公开数据泄露或敏感状态变化。

因此，`tools/list` 成功只能支持 U1，不能直接证明 U2 或 U3。最终结论由测试人员结合原始响应、预期标记、授权范围和实际安全影响，通过 `review` 记录为 `confirmed`、`not_confirmed` 或 `needs_more_evidence`。

## 7. 结果与可复现性

每次运行都会保存目标指纹、风险候选、测试计划、调用结果和人工结论。`targets-report` 可生成汇总报告，`targets-diff` 可比较两次扫描中的新增目标、消失目标、风险变化和工具变化。

这种设计将“目标发现”“风险推断”和“漏洞确认”分开，既能提高批量测试效率，也能保留完整证据链，便于复核实验结果和更新论文数据。

## 8. 各命令对应的阶段

| 命令 | 作用 | 是否连接目标 | 是否调用工具 |
|---|---|---:|---:|
| `targets-discover` | 从公开索引收集候选地址 | 否 | 否 |
| `targets-scan` | 批量识别 MCP 服务和工具清单 | 是 | 否 |
| `discover` | 探测单个 MCP 服务 | 是 | 否 |
| `targets-report` | 生成扫描汇总报告 | 否 | 否 |
| `targets-diff` | 离线比较两次扫描 | 否 | 否 |
| `audit` | 识别高风险工具并生成测试计划 | 是 | 否 |
| `one-click` | 合并探测、筛选、计划和可选单次调用 | 是 | 默认否，显式批准后一次 |
| `execute` | 审批后执行一次受控调用 | 是 | 是，一次 |
| `review` | 记录人工漏洞结论 | 否 | 否 |
